# Carta / Pulley Export Column Mapping

This document maps the Carta and Pulley cap-table export formats to the
cap-table skill's canonical artifact schemas (`inputs.json`,
`instruments.json`, `cap_state.json`).

**Status:** Carta mapping **verified against real Carta exports** (10
real exports from the private corpus, spanning 5 different companies).
The fingerprint, sheet structure, and Convertible Ledger column
conventions documented below are derived from actual files, not docs
guesses.

Pulley mapping remains skeleton-only — no real Pulley exports in either
test corpus to verify against. Implementation deferred until a real
Pulley XLSX is available.

---

## 1. Format detection (sheet fingerprint) — VERIFIED

`extract_cap_table.py` distinguishes the supported XLSX formats by
sheet-name fingerprint. Whitespace is stripped from sheet names before
comparison (real exports occasionally have trailing spaces).

| Format | Distinguishing sheet name(s) | Source verification |
|---|---|---|
| **Carta default** | `Summary Cap Table` (always), often + `Intermediate Cap Table` + `Detailed Cap Table` | 10/10 real Carta exports in corpus 2 |
| **Carta + per-class ledgers** | Above + `{ClassPrefix} Ledger` (e.g. `CS Ledger`, `PS1 Ledger`, `PA1 Ledger`, `PB1 Ledger`, ...) + `Convertible Ledger` + `{Plan Name}` for the equity-incentive plan + `Data Warnings` + `Summary by Cost Center` + `{ClassPrefix} Warrant Ledger` | Larger Carta exports (1 of 10 was this form; 27 sheets total) |
| **Carta OCX standard** | `Capitalization by Stakeholder`, `Voting Details`, `Context` | OCX repo on GitHub; 0 real exports in corpus (rarely used in practice) |
| **Pulley** | `Ownership` + contract-specific tabs: `Shares`, `SAFEs`, `Convertible Notes`, `Stock Options`, `RSAs`, `RSUs`, `Warrants` | Pulley help docs; 0 real exports in corpus |

If none match, the script routes to `--mode=freeform` and dispatches the
Context-A `SPREADSHEET_STRUCTURE_DETECTION` sub-agent.

## 2. Carta banner + header-row contract — VERIFIED

Every Carta sheet has a deterministic 3-row prelude:

| Row | Content |
|---|---|
| Row 1 | (typically blank or company logo) |
| Row 2 | `{Company} {Sheet Title}` — e.g. `Acmecorp Summary Cap Table`, `Foobar Intermediate Cap Table` |
| Row 3 | `As of {M/D/YYYY} • Generated by {user identifier}` |
| Row 4 | (blank) |
| Row 5 | **Column headers (actual data starts row 6)** |

Company name extraction: split row 2 by " Summary Cap Table" / " Intermediate Cap Table" / " {Sheet Type}" — the prefix is the company display name. Note this is NOT always the Carta URL slug (a company can have a slug like `acmecorp-inc` but a different display name like `Foobar`, typically after a rebrand).

As-of date extraction: regex `^As of (\S+)` against row 3; convert M/D/YYYY → ISO.

## 3. Field-level mapping per Carta sheet — VERIFIED columns

### 3.1 Summary Cap Table (always present)

Carta's high-level rollup. Row 5 headers (verified columns):

| Carta column | Maps to |
|---|---|
| (col A, blank header) | Row label: `Common Stock classes` (banner), `Common (CS) Stock`, `Series Seed-1 Preferred (PS1) Stock`, ..., `Total Common Stock issued and outstanding`, `Total Preferred Stock issued and outstanding`, etc. |
| `Shares Authorized` | `cap_state.preferred_series[].shares_authorized` (preferred classes), `cap_state.option_pool.authorized` (option pool row) |
| `Shares Issued and Outstanding` | `cap_state.preferred_series[].shares` (count of issued preferred); `cap_state.option_pool.issued_and_outstanding` |
| `Fully Diluted Shares` | not directly mapped (we compute from instruments + cap_state) |
| `Fully Diluted Ownership` | not stored (we compute) |
| `Cash Raised (USD)` | (informational; flows into scenario context, not instruments) |
| `Fully Diluted Shares with Draf` | (if drafts column present; ignore for now) |
| `Fully Diluted Ownership with D` | (drafts ownership; ignore) |

### 3.2 Intermediate Cap Table

Per-stakeholder × per-class breakdown. Row 5 headers (verified):

| Carta column | Maps to |
|---|---|
| `Stakeholder ID` | (Carta internal hex ID — used to join across sheets) |
| `Name` | `cap_state.founders[].name` (when founder), `instruments.option_grants[].holder_id`, etc. |
| `Common (CS)` | per-stakeholder common share count |
| `Series Seed-1 Preferred (PS1)` | per-stakeholder PS1 count |
| `Series Seed-1 Preferred (PS1) 1.1` | per-stakeholder PS1 as-converted count (note the ` 1.1` suffix — Carta uses this for as-converted) |
| (per-class repeating, pairs of: shares + as-converted) | ... |

**Critical pattern:** Carta repeats each preferred class with `[blank]` and ` 1.1` suffixes — the former is the issued share count, the latter is the as-converted-to-common count. Use `original_conversion_price` / `current_conversion_price` from the per-class Ledger sheets to verify the ratio.

### 3.3 Detailed Cap Table

Same structure as Intermediate but with additional per-transaction detail columns. Useful for verifying ledger consistency; not parsed directly by the extractor (the per-class Ledgers carry the same data more cleanly).

### 3.4 `{ClassPrefix} Ledger` (per share class)

Per-security ledger. Sheet name pattern: `CS Ledger`, `PS Ledger`, `PS1 Ledger`, `PA1 Ledger`, ..., `PBB1 Ledger`, `PC1 Ledger`, `PC2 Ledger`, `CS Warrant Ledger`, `{Prefix} Warrant Ledger`. Row 5 headers (verified from CS Ledger + PA1 Ledger):

| Carta column | Maps to |
|---|---|
| `Formatted Security ID` | Display ID (e.g. `CS-001`, `PA1-001`) |
| `Security ID` | Internal ID (e.g. `CS-1`, `PA1-1`) |
| `Stakeholder Name` | `cap_state.founders[].name` (founder rows) or `holder_id` lookup |
| `Stakeholder Email` | (informational) |
| `Quantity Issued` | `cap_state.common_batches[].shares` (CS) or `cap_state.preferred_series[].shares` (preferred) |
| `Quantity Outstanding` | (post-cancellation/forfeiture count; usually `Quantity Issued` minus `Quantity Canceled`) |
| `Share Class` | e.g. `Common (CS)`, `Series A-1 Preferred (PA1)` |
| `Price Paid Per Share` | `cap_state.preferred_series[].original_issue_price` (preferred), `cap_state.common_batches[].consideration / shares` |
| `Company-Provided Price Per Share` | (informational; usually equal to Price Paid) |
| `Share Class Original Issue Price` | `cap_state.preferred_series[].original_issue_price` (the per-class OIP) |
| `Cash Contributed to Company` | per-security cash; aggregates to `Cash Raised (USD)` |
| `Vesting Schedule` | text; parse into `cap_state.common_batches[].vesting` for RSAs |
| `Vesting Start Date` | date |
| `Issue Date` | `cap_state.preferred_series[].issuance_date` / `cap_state.common_batches[].issuance_date` (Gotcha #8: QSBS uses `stock_issue_date` per §6 alias) |
| `Board Approval Date` | date |
| `Termination Date` | date; nullable |
| `Canceled Date` | date; nullable — when present, record was cancelled |
| `Quantity Canceled` | shares cancelled |
| `Cancellation Reason` | text (e.g. `Conversion`, `Repurchase`) |

**Cancelled records:** When `Canceled Date` is non-null, the security has been cancelled (converted, repurchased, forfeited). Skip these records when building the current cap state.

### 3.5 Convertible Ledger — VERIFIED

The most important sheet for our skill. Row 5 headers (22 columns; verified):

| Carta column | Maps to (cap-table canonical) | Notes |
|---|---|---|
| `Formatted Security ID` | `safes[].id` / `convertible_notes[].id` (display form) | `SAFE1-01`, `SAFE2-03`, `CN-001` |
| `Security ID` | (internal ID) | `SAFE1-1`, `CN-1`; **SAFE prefix `SAFE\d*-\d+` is how we distinguish SAFEs from notes** |
| `Stakeholder Name` | `safes[].investor_name` / `convertible_notes[].investor_name` | |
| `Stakeholder Email` | (informational) | |
| `Principal` | `safes[].purchase_amount` / `convertible_notes[].principal` | |
| `Other Consideration` | (ignored for v0.1) | |
| `Interest` | `convertible_notes[].principal` × `annual_interest_rate` × time (already accrued in Carta's view) | |
| `Total` | `Principal + Interest` (computed; ignored) | |
| `Destination` | (ignored) | What the convertible converts INTO; informational |
| `Issue Date` | `safes[].issuance_date` / `convertible_notes[].issuance_date` | datetime → ISO |
| `Board Approval Date` | date; nullable | |
| `Termination Date` | (paired with cancellation) | |
| `Canceled Date` | **non-null → skip this record (already cancelled)** | |
| `Cancellation Reason` | `Conversion`, `Repayment`, etc. | |
| `Converted Date` | **non-null → skip this record (already converted)** | |
| `Maturity Date` | `convertible_notes[].maturity_date` | nullable for SAFEs (use sentinel `9999-12-31`) |
| `Interest Rate` | `convertible_notes[].annual_interest_rate` | already decimal (0.06 = 6%); leave as-is |
| `Valuation Cap` | `safes[].post_money_valuation_cap` / `convertible_notes[].valuation_cap` | money; 0 → treat as null |
| `Conversion Discount` | `safes[].discount_multiplier` / `convertible_notes[].discount_multiplier` | **MUST normalize via `extract_cap_table._normalize_discount`** — Carta stores percent-as-fraction (0.2 = 20% discount); the canonical form is the multiplier (0.80 = 20% discount). Per Gotcha #3. |
| `Change In Control Percent` | (not modeled) | |
| `Conversion Trigger` | (informational; usually a money amount for qualified-financing threshold) | |
| `Note Block Name` | (informational; e.g. `SAFE1 Notes`, `2023 Bridge Notes`) | groups SAFEs by template |

**SAFE vs Note distinction:** Security ID prefix `SAFE\d*-\d+` (case-insensitive) → SAFE; everything else → convertible note. Verified pattern in real exports.

**SAFE form inference (when SAFE):**

| `Valuation Cap` | `Conversion Discount` | Inferred form |
|---|---|---|
| non-null + > 0 | null or 0 | `yc_postmoney_cap` |
| non-null + > 0 | non-null + > 0 | `cap_plus_discount` |
| null or 0 | non-null + > 0 | `yc_postmoney_discount` |
| null or 0 | null or 0 | `other` (counsel-review; possibly uncapped MFN) |

### 3.6 `{Plan Name}` (e.g. `2017 Equity Incentive Plan`)

Per-grant ledger. Row 5 headers (verified):

| Carta column | Maps to |
|---|---|
| `Formatted Security ID` | `option_grants[].id` (e.g. `ES-003`) |
| `Stakeholder Name` | `option_grants[].holder_id` lookup |
| `Quantity Issued` | `option_grants[].shares_granted` |
| `Quantity Outstanding` | (= issued - cancelled - exercised - forfeited) |
| `Plan Name` | (informational; e.g. `2017 Equity Incentive Plan`) |
| `Issue Date` | (informational; the GRANT-DATE column is separate) |
| `Exercise Price` | `option_grants[].strike_price` |
| `Base Award Type` | `INTL` (international/Israeli §102), `ISO`, `NSO` — used to derive `plan_type` |
| `Is ISO/NSO Split?` | (informational) |
| `Vesting Schedule` | text; parse to `option_grants[].vesting` |
| `Vesting Start Date` | (informational) |
| `Total Time Vested Quantity` | `option_grants[].shares_vested_to_date` |
| `Outstanding Vested Quantity` | (vested + not exercised) |
| `Outstanding Unvested Quantity` | |
| `Quantity Exercised` | `option_grants[].shares_exercised` |
| `Termination Date` | nullable |

**§102 sub-type detection (Israeli context):** Carta uses `Base Award Type: INTL` for international/Israeli grants but does NOT distinguish §102(b) capital-gains / §102(c) ordinary-income / §3(i). When the engagement jurisdiction is Israeli AND Carta's award type is `INTL`, prompt the founder via `AskUserQuestion` for the specific §102 sub-type.

### 3.7 Data Warnings

Carta's own integrity warnings (e.g. exercise dates before grant dates). Row 5 headers:

| Carta column | Use |
|---|---|
| `Security ID` | linked record |
| `Security Type` | `Warrant`, `Stock Option`, etc. |
| `Code` | Carta error code (`W030`, etc.) |
| `Warning` | text description |

**Action:** propagate any Carta data warnings into our own `extraction_audit.json` so the founder sees them too. Don't silently ignore — they often indicate real data-quality issues.

## 4. Known quirks (documented from real exports)

- **Banner + headers offset**: row 5 is the actual header row (rows 1-4 are banner/title). The `_find_header_row` heuristic in `extract_cap_table.py` matches this.
- **Discount stored as percent-as-fraction (Gotcha #3)**: Carta's `Conversion Discount: 0.2` means 20% discount → multiplier 0.80. Always run through `_normalize_discount`.
- **Cancelled/converted records**: any non-null `Canceled Date` or `Converted Date` means the security is historical; skip when building current state.
- **Carta URL slug ≠ company display name**: companies can rebrand without updating their Carta URL slug, so the slug in the filename may differ from the display name shown in the workbook's row 2 banner. Always pull the company name from row 2 banner, not the filename.
- **Filename pattern**: Carta downloads are named `{slug}_YYYY-MM-DD_{sheet_list}.xlsx` (e.g. `acmecorp-inc_2026-05-18_summary_cap_intermediate_cap_detailed_cap.xlsx`). Filename pattern alone is NOT enough to confirm Carta format — must inspect sheets.
- **Maturity Date null for SAFEs**: SAFEs have no maturity; we substitute `9999-12-31` sentinel so the schema accepts it.
- **`Quantity Issued: 0` rows**: appear when a stock class is authorized but has not yet been issued; skip in the per-class ledger pass.
- **As-converted-to-common columns marked `1.1`**: e.g. `Series Seed-1 Preferred (PS1)` and `Series Seed-1 Preferred (PS1) 1.1` — the latter is the as-converted count. Use OCP / current_conversion_price to verify; AD adjustments are reflected here.
