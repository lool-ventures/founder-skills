# cap-table cowork-harness tests

Token-free **replay** PR gate (`.github/workflows/cowork-replay.yml`) over committed cassettes that
exercise the `cap-table` skill under Claude Cowork's runtime via
[`cowork-harness`](https://github.com/yaniv-golan/cowork-harness) (≥ 0.3.0). Recording is **live**
(needs the staged agent + Docker); replay/verify are **token/agent-free** (stock CI).

## Layout
- `sessions/` — repo-relative sessions: the **environment** (model, plugin mount, file `uploads:`).
  All mount the **whole** `founder-skills` plugin (`local_plugins: [../../../]`) — never the
  `skills/cap-table/` subdir (see Constraints). Uploaded fixtures live here (`uploads:` is a
  session-only key per cowork-harness — scenarios have no upload field).
- `scenarios/` — one YAML per test: the **interaction** (prompt + scripted answers + `assert:`),
  pointing at a session via `session:`.
- `fixtures/` — synthetic Lane-1 PDFs (generated by `gen_lane1_fixtures.py` from the synthetic
  `cap-table-eval` sources) + the synthetic Carta XLSX. **Synthetic data only.**
- `cassettes/` — recorded cassettes, committed. The replay gate runs against these.

## Record (local / self-hosted only)
```bash
export COWORK_AGENT_BINARY="$HOME/Library/Application Support/Claude/claude-code-vm/<ver>/claude"
export COWORK_HARNESS_RUNS_DIR=/tmp/ct-cowork-runs        # MUST be outside the mounted plugin tree
cd founder-skills/tests/cowork
cowork-harness record scenarios/<name>.yaml --out cassettes/<name>.cassette.json
```
Re-record after any change to `cap-table` SKILL.md / scripts / `cap-table-rules.json`.

## Replay (CI / token-free)
```bash
cowork-harness replay cassettes/                 # replay every *.cassette.json (0.4.0 dir mode)
cowork-harness lint scenarios/*.yaml             # no-silent-false-green (0.4.0 CLI subcommand)
# Privacy + staleness gate (canonical allowlist is in .github/workflows/cowork-replay.yml): synthetic
# currency, agent/host + citation domains (claude/anthropic/github), the XLSX XML namespace, and the
# reserved example.com (synthetic Carta data).
cowork-harness verify-cassettes cassettes/ \
  --allow '\$\s*\d[\d.,]*\s*(?:[MmKkBb]|million|thousand|billion)?' \
  --allow 'claude\.com' --allow 'anthropic\.com' --allow 'openxmlformats\.org' \
  --allow 'example\.com' --allow 'github\.com'
```

> **Staleness** (re-enabled on cowork-harness ≥ 0.4.0 — the skill hash now excludes `*.cassette.json`).
> A `[stale] baseline moved …` finding **locally** is expected when your Cowork Desktop is ahead of the
> harness's shipped baseline (cassettes stamp the shipped pin); a hosted CI runner has no newer Desktop,
> so it doesn't fire. A `[stale] skill/plugin dir contents changed` finding means a cap-table
> SKILL/script/rule edit landed without a re-record (see Record above).

## Constraints (do not break)
1. **Whole-plugin mount** — the session mounts `../../../` (the plugin root) so the rule pack +
   shared scripts are in scope. Narrowing to `skills/cap-table/` reintroduces non-determinism /
   stale-fingerprint gaps.
2. **`COWORK_HARNESS_RUNS_DIR` outside the plugin** — the ephemeral run dir must not live under
   `founder-skills/` (else the harness copies the plugin into a subdir of itself → recursive-copy
   error, and pollutes the skill hash).
3. **Synthetic data only** — cassettes are committed; never record against a real company/founder/
   cap table. The `verify-cassettes` privacy scan is the backstop, not the only guard.
