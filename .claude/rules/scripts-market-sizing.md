# Market Sizing Scripts

- **`market_sizing.py`** — TAM/SAM/SOM calculator (top-down, bottom-up, or both). Also the only place FX happens. On the skill's path (inputs by reference, `--validation --inputs`) the rate is a sourced `fx_rate` entry in `validation.json` with from/to/as_of and a listed source; `--fx-rate` and `*_currency` flags are refused (`E_FX_ON_REFERENCE_PATH`), a missing rate is `E_FX_RATE_MISSING` (remedy `record_research`), and a rate is never inverted. The legacy numeric path still takes `--fx-rate`/`--fx-as-of`/`--fx-source`; there a declared foreign currency with **no** rate is a hard error, never a guess. Conversions are recorded in `sizing.json`'s `fx` block and disclosed to the founder in both `report.md` and `report.html`; the recorded `converted_value` IS the number the math consumed, which is what lets `compose_report.py` compare a founder-stated figure across the conversion.
- **`sensitivity.py`** — Stress-test assumptions with low/base/high ranges and confidence-based auto-widening. **RECONCILES rather than defers:** a range's own `confidence` used to be absolute, which let a caller tag a medium-confidence parameter `sourced` and escape widening entirely; the stricter of the declared and cross-referenced tiers now wins (it can only ever WIDEN). `confidence_source` on each scenario records where the tier came from — `range` / `validation` / `reconciled` / `default` — because "no widening happened" and "no widening was called for" were previously the same artifact. With `--sizing`, base values come from `sizing.json` (`base_source`, `graded_against`), and a founder-stated input the agent left unranged is varied at least ±30% and across `founder_stated_alternatives`.
- **`checklist.py`** — Validates 22-item self-check with pass/fail per item; `--sizing` stamps `graded_against`, and `--inputs` adds the inputs it graded, so a later edit to `inputs.json` names the checklist stale
- **`compose_report.py`** — Assembles report from artifacts, validates cross-artifact consistency
- **`closing_message.py`** — Prints the founder-facing hand-over message from `report.json`, and writes the same text to `handover.txt` beside the report for the check that runs after. It carries the report's own `verdict` paragraph — the words the page opens with — because a message that asked the founder to go read the verdict was measured 0/2 at hostloop: the model dropped the pointer and wrote the verdict itself, with its own rounding. Composing this message in chat is what it replaces. Refuses (exit 2, nothing printed or written, no `handed_over_at`) a report.json whose `run_id` is another run's than the folder's inputs carry (`RUN_ID_MISMATCH`); a missing id on either side is not compared. Every compose stamps that top-level `run_id`, last. When the run that holds the folder recorded `FS_HOST_NO_HANDOVER` (all three closers, via `host_delivers` in the skill's gates module; a bound folder whose current run cannot be told, or whose ledger cannot be read, exits 2), it prints only `_handover_check.HOST_DELIVERS_LINE`, writes that to `handover.txt` (a failed write removes the older file and still prints; exit 2 only when neither works) and stamps `handover: "host"` on the run the flag was read from, after every refusal above.
- **`_upload_names.py`** — The founder's filenames as uploaded: the cloud-lane `<8-hex>-` upload prefix is stripped at RENDER time (compose's final markdown + `verdict`, and visualize's adversarial section + verdict, where it runs BEFORE `_esc` or an escaped `'`/`&` stops matching), and once in the review's prose at pipe time: `red_team.py` maps it after `humanize_review_text`, which protects the stored names and every name as uploaded except one of our own files' names, each as a whole token (so an upload named like one of our files cannot shield our own mention, and a founder's own file is never called ours), and before the policy's substitute, which would rewrite a word inside a prefixed name. It is not renamed at the source, because `red_team.py` opens `<uploads-dir>/<file>` and the OCR sidecars key on it, so citations, quotes and source lists keep the stored names. The payload builder is untouched: its review sentences carry what the stored review carries (uploaded names, from a piped review), and `test_upload_names.py` pins by whole-payload equality that the render-time map does not reach it. Not covered: checklist notes and estimate reasons pass the policy before compose's map (`_view._founder_prose`), and visualize never maps them. Stripping needs EVERY known name to be prefixed; a batch of one needs an a-f letter, since `20240115-deck.pdf` is a date; a collision keeps the prefix. The root fix is to strip while mirroring in Step 6c, but that is a SKILL.md change and cannot be exercised on the lane it targets. competitive-positioning carries a byte copy (held by `test_cp_upload_names.py`), applied differently: its names are this run's review copies plus its `handoff/<run_id>/docs` mirror (`_cp_redteam_copy.upload_display`, never `redteam.json`), `cp_red_team.py` strips them in the review's prose at pipe time, after its own wording and with the same protected set as market-sizing's (before the policy's substitute rewrites a word inside one), compose maps report.md after the quote lift and before the policy, `criterion_text` maps checklist evidence first, and both pages map every loaded artifact (`humanize_tree`, `evidence_quote` excepted). The stored review's prose therefore carries the uploaded names (its citations, quotes and source lists keep the stored ones), so the coaching payload's outside-review sentences do too, while its other fields keep the stored names.
- **`_params.py`** — One owner of each sizing figure's unit and print format (money/count/percent), and of the builds' gap as a factor.
- **`_provenance.py`** — Resolves inputs by reference (assumption / founder_stated / derived / estimate) into value, unit, normalisation, grade and entries; refuses unit mismatches with a remedy_kind. `check_bases`: each segment or serviceable share (percent, fraction or ratio) must record `of` naming an entry its base is built from (counts and money totals only), another share of the same step (stamped `chain`, since a 100% head can carry any share), or carry a `proxy` bound to that base; a step dividing two counts must divide by a base entry or carry a `proxy` on one; otherwise `E_RATE_BASE_MISSING` / `E_RATE_BASE_MISMATCH` (remedy `record_research`; the mismatch names the chain exit when the step has another share). A proxy on an entry whose `of` is a base entry (by name, or its name or label in other words) is `E_RATE_BASE_PROXY_SELF`: it would read "measured on X, applied to X as a proxy". `market_sizing.py` keeps every refused share and its `of` in `handoff/<run_id>/base_rejections.json` (append-only, like `unit_rejections.json`); `_view.sizing_integrity` raises `POPULATION_CHANGED_AFTER_REJECTION` (high, disclose) when the sizing uses one under another `of` than its first refusal's, except `of` naming a share of the same step measured on the base. It is the one integrity code report.html also states (beside the proxy sentences), because its silent form leaves nothing else to read. Unseen: a rewrite before any refusal, a deleted file, a fresh run id. Stamped as `base_checks`; a replay of an unstamped sizing is not checked. The algebra admits no count × count and no sum, so a base holds one population. `of` and `proxy` are in the review's record snapshot (an edit after the review is `RECORD_CHANGED_AFTER_REVIEW`) and out of the redo digest. `_view.base_sentences` renders each proxy and each `base_changed` on both pages.
- **`_view.py`** — One owner of every founder-visible figure and derived fact for compose and visualize: verdict and "Short answer", sizing-integrity codes, claim ranges and disagreements, checked multiples.
- **`_quote_value.py`** — Whether a research entry's recorded figure is written in its `quote` (the passage of the source that states it; `references/web-sources.md` says when the main thread records one). Unit-aware, at the written number's own precision capped at 5% (deck-review's `ledger.py` rule, re-implemented); `fx_rate` and unknown units never match. `market_sizing.py` stamps `quote_checks` per entry in `sizing.json` (absent when a name repeats), and `_view.quote_sentence`, rendered in report.md's Sources Used and report.html's Assumption Confidence, counts the sourced market figures the sizing uses (exchange rates aside) and how many have a matching passage; no stamp, or a counted entry the stamp lacks, means no sentence. It proves only that recorded text contains the figure: a snippet or a paraphrase passes, and the wording claims nothing more.
- **`record_revision_answer.py`** / `_revision_answer.py` — Records Step 6d's deliver-or-revise answer; its absence, when an accepted high finding names a parameter, raises `REVISION_NOT_OFFERED` (with a run ledger, compose instead applies the request's answer through the same path, or under `FS_HOST_NO_ASK` with none sent takes `deliver`, disclosed, and otherwise exits 10 asking for it). `--from-pre-answer` opens the question and applies the request's answer.
- **`_ms_gates.py`** — market-sizing's gate checks for its generator, producers, compose and closer (exit 10 naming the question, `RUN_FINISHED`, `RUN_ID_REQUIRED`; a named run goes through `_run_ref.refuse_not_this_runs`, so an id not bound there is `RUN_NOT_BOUND` and one a later bind replaced is `RUN_SUPERSEDED`); the parts it shares with `_fmr_gates.py` are copies held to it by a test. `refuse_finished_write` is the delivered-analysis guard: compose, `market_sizing.py`, `sensitivity.py`, `checklist.py`, `red_team.py` (imported late, after the shared-scripts refusal a lone copy must meet first) and the generator (every context, `--redo` included) refuse `RUN_FINISHED` before any write on a `complete` or `refused` run, with or without a changed answer; keyed on the output folder's own ref, so a what-if outside the run folder never meets it. The page, the closer, a repeated coaching insert and `deliverables --final` do not call it.
- **`dispatch_prompt.py`** — Generates the RED_TEAM, CHECKLIST and the two sizing sub-agent dispatches (TOP_DOWN_METHODOLOGY, BOTTOM_UP_METHODOLOGY; the sizing prompts refuse, exit 10, until the approach and any two-figure choice are recorded for a run with a ledger) from identifiers on disk (CHECKLIST reads a methodology copy with the revision record stripped, so the grader grades the analysis as it stands): the model supplies paths and ids, every sentence comes from this file, and the e2e lane regenerates the prompt and asserts the dispatched one is byte-identical. A sizing build the comparison flagged (`comparison.warning` / `sam_warning` / `som_warning`) may be printed once more per run with `--redo comparison` (a value-taking option, so the dispatch hook's subcommand reading holds; `--suspect <input>` from the build's own inputs): the generator writes the block (flagged levels, never a figure or which build is higher, and the only files the sub-agent may open), records the print (`_sizing_redo.py`), and refuses with `SIZING_REDO_*` codes (no context line on stdout; on a finished run the redo is refused like every print, `RUN_FINISHED` in the shared `rejected` shape); a plain print of that build while its redo has not reached the sizing is `SIZING_REDO_PENDING`, until the run has moved past the sizing (then a new redo is TOO_LATE and Step 6d needs the plain prompt); only a producer's rejection reprints a consumed redo. A usage error naming the sensitivity step adds a `fix:` line: SENSITIVITY_TEST has no generator, and the line names the SKILL.md heading whose template to send. The founder's documents are listed FIRST, before any of our artifacts — a reader who opens the analysis's reading of the deck before the deck inherits its frame, and the step exists to escape the constructor's framing.
- **`_sizing_redo.py`** — The comparison redo's record (`sizing_redo.json`, and with a ledger the same record in the ledger under `sizing_redo`, written in a transaction, read first, so deleting the file neither erases the disclosure nor reopens the budget; with a ref and an unreachable ledger every reader refuses, never reading the file; a finished run is refused before it, by the generator's `_ms_gates.refuse_finished_write`); the ONE `consumed` predicate (the redo hand-off's gate record has `gated_at` after the print AND the file's mtime is after it AND the sha matches; no fallback), used by the generator's SPENT and by `fill_after`, which `market_sizing.py` runs to record, once, the gap the redo produced and which research entries the sizing uses were added or changed since the first print (a per-entry digest, the label, the quote, `of` and `proxy` excluded). Once `after` is written, the outcome is the record's alone: Step 6d's sizing re-dispatch runs before HANDOFF_DIR points at `r2/` and rewrites round 1's hand-off, which must not turn a redo that ran into "not run". Compose's `SIZING_REDO_NOT_RUN` (medium, not acceptable; exactly when `after` is absent) and the report sentence (`_view.redo_sentence`, both surfaces, through the founder-text policy) read only the record. Residuals, stated in its docstring: the budget limits prints, not dispatches (the identical redo prompt can be sent again; the e2e lane counts dispatches, a run does not); with no ledger, deleting the file or a fresh run id resets it; the redo sub-agent may open its own OUTPUT_PATH (the file tool reads an existing file before overwriting it).
- **`ocr_uploads.py`** — Writes a machine-read text sidecar per page of every image-only upload, so a red-team citation to a scanned page can be checked against text rather than re-read by vision. Binary-only (`pdftoppm` + `tesseract`, the cap-table pattern) with NO Python OCR dependency: when either binary is absent it exits 0 with `ocr_available: false` and writes only its receipt (no sidecars), every document citation stays `quote_verified: null`, and that is disclosed. A missing OCR binary must never block a run. It writes `<out>/receipt.json` per document as it goes, so a re-run after a timeout RESUMES; `dispatch_prompt.py` refuses (exit 2) while any image-only PDF is not covered by the receipt — an `ocr_available: false` receipt counts as covered.
- **`visualize.py`** — Generates self-contained HTML with SVG charts; outputs HTML (not JSON)
