# Hooks

- **SessionStart** (`founder-skills/scripts/session-setup.sh` → `compaction_reread.py`): two jobs. (1) Writes `CLAUDE_PLUGIN_ROOT` into `CLAUDE_ENV_FILE`, single-quoted. Nothing reads that: no script reads the variable, and Step 0 resolves the root itself. SKILL.mds use the braced token, which Claude Code's loader substitutes, except in a skill invoked on cloud before the conversation's first turn that needs a shell or file tool. Whether the hook fires in a cloud session is unverified (a cloud task leaves no local session dir to inspect); since nothing reads the variable, either answer is harmless there. (2) On `source: "compact"` only (matched in the shell on the runtime's compact JSON, so no other session start launches an interpreter), the body adds one `additionalContext` note: the re-attached SKILL.md was cut before Step 1, so Read it from the `### Step` the run is on, with the run's own shell paths (`scripts_dir_shell`, `shared_scripts_dir_shell`) from its status file. It speaks only when the main thread started a founder-skills skill (`dispatch_type_check.invocations`: a `Skill` call or a typed slash command, never a skill name a tool returned) and the latest `start` result's status is `running` or `waiting` for that skill; a finished run is never told it is open. The runtime fires the same event for an ordinary sub-agent's compaction with an identical payload, so the note opens "If you are the main thread running …" and ends "If you are a sub-agent, ignore this"; that wording is the only separation. It lands after the cut copy, last in context; whether the note changes behaviour is not yet measured. POSIX `sh`, fails open (every path exits 0; a missing body is one stderr line), its body held to the hooks' Python floor. The Stop hook's no-ask end (`NO_ASK_END_REASON`) adds a re-read sentence when a main-thread `compact_boundary` follows the request. Every Stop-hook window (hand-over, delivery, review page, no-ask) starts at the founder's latest message: a compaction summary row (`isCompactSummary`) and a background agent's result delivered as a user row (`origin.kind` not human, or text opening `<task-notification>`) are not prompts.
- **Stop** (`founder-skills/scripts/stop-handover-check.sh` → `stop_handover_check.py`): after the model's final turn, checks that the founder's message carries the printed hand-over whole and adds nothing numeric, for each skill in its `SKILLS` table (market-sizing's `closing_message.py`, competitive-positioning's `cp_closing_message.py`, financial-model-review's `fmr_closing_message.py`; each trigger matched as a whole script name, the last closing call of the prompt deciding, each skill reading only its own `handover.txt`, or — when none is under the payload's `cwd`, which at the host-loop spawn newer Desktop uses is `/var/empty` — the same text sliced from the transcript's record of its closing call's output, opener line to closing offer, with a cut-short result not used, and only the last closing call's result read, never an earlier one's); a `{"decision": "block", "reason": …}` reply sends the model back **once**. When the request names its reply tool (`FS_HOST_REPLY_TOOL <tool_name> <input_key>`, read from a founder's own message only — any prompt of the session, last valid line wins, `<command-args>` unwrapped, never the run's ledger, whose lines the model types into `run_status.py start`, so a ledger route would let the model name any tool as the founder's message) and the turn sent through that tool after the closing call (exact name, the named input a non-empty string, main thread, result not `is_error`), the sends alone are that message: plain text and the payload's last text are not read. With the line and no send, the plain text is judged as before, so a hand-over written only as plain text passes (an accepted residual: blocking it would block every run on a host whose tool calls do not reach the transcript). Whenever the line names the tool, send or not, a block asks for the follow-up through it, in the reason's lead sentence, never beside `CORRECTION_LEAD`. The line is looked for only on a stop whose prompt ran a closing script; one the hook's copy of the shape rejects is ignored with a stderr line. Without the line, the judgement is unchanged. On `stop_hook_active`, and only after a hand-over block (the feedback row carries `CORRECTION_LEAD`), it judges the follow-up (through the reply tool when named) and writes one stderr line (`second stop: hand-over passed` / `… failed: <why>`), never a second block; after a delivery or no-ask block it writes nothing. Not exercised on any lane or recording: only a host run with the line proves it live (owed). When that last call failed (`is_error`, or a `[exit N]` lead) and printed no hand-over — a closer refusing another run's report — nothing is judged against any `handover.txt` (the one on disk is an earlier run's): the block names the refusal and asks to compose again and re-run the closer, never dictating a hand-over. A closer the shared-/tmp check held (`[shared-tmp][<path>]` after the runtime's hook-error prefix) never ran: the block names the path and asks to run it again with no redirect into the shared temp folder, without repeating the marker, which that check would count as a hold. The same hook also checks DELIVERY (`_delivery_check.py`): when a founder-skills report build succeeded in the prompt through a shell tool, no shell call failed after it (one the shared-/tmp check held, its result carrying `[shared-tmp]` after the runtime's `PreToolUse:<tool> hook error: ` prefix, never ran and is not a failure), the text after the build (restarting after a hook's feedback turn; a reply tool's sends are not read here) links or names a deliverable (for a closing script's build, carrying its printed hand-over whole counts, since on cloud those name each file by label alone), the host offered a delivery tool (a name containing `present_files`, or `SendUserFile`, in the transcript's `prompt_snapshot` tools or `deferred_tools_delta`), and no delivery call followed the build (the prompt's last compose when it ran one, so a delivery before a closing script that follows still counts), it asks the model to attach the files. A connected-folder write (`…__device_commit_files`, served on cloud as `mcp__remote-devices__device_commit_files`) is counted as delivery by the cassette checker (`cowork-tests/delivery_check.py`, suffix-matched), not by this hook. On the cloud lane the three closers print each document's label without a path (a path there is dead text beside the file card), so there only the carried hand-over names a deliverable; the reason says the message "points the founder to" the files, true either way. Known gap: a cloud closing message rewritten without the hand-over and without a path is not asked to attach. It never fires on the plain CLI (`entrypoint: cli`), on a host that offers no delivery tool, or on a transcript that records no tool list. Measured 2026-09-29: it fires on the three real link-only misses and on none of the runs that delivered. Both checks share one block; when both fail, the delivery comes first and the printed hand-over is sent last, because nothing after the rewrite is checked. Only when neither fires, a third ask (`missing_review_delivery`, its own conditions, not the report check's message-shape one): financial-model-review's static review page (`review_inputs.py … --static`) built in the prompt, no successful delivery naming the page, no report build and no `AskUserQuestion` after it (one the PreToolUse check held does not count), a delivery tool offered, not the CLI — a turn that ended WAITING at the values check. Its reason names the pending question and never calls the run finished. A review-page delivery is not the report's and the report's is not the page's; a `record_gate_answer.py` call is neither a build nor a delivery. A block APPENDS — the faulted message stays on screen and the rewrite lands beneath it — so the reason dictates a follow-up the founder will read, not an internal note. Its lead (`CORRECTION_LEAD`) states provenance and which figure wins on a conflict, never that the message above was wrong: neither failure `_handover_check.py` reports establishes a wrong figure (a correct paraphrase fails containment too), and a production block once told a founder to disregard figures that were right. The wrapper is POSIX `sh` (it runs host-native on macOS at hostloop and under dash in the Cowork VM) and **fails open** when `python3` is absent or the hook's Python file is missing: the hook enforces, the skill never depends on it. It fires at the end of EVERY turn in every session with the plugin enabled; any stop in which the current prompt ran no closing script, no successful report build and no successful static review build exits 0 with no output, and any error exits 0 with one stderr line. The Stop event can arrive before the final text reaches the transcript file, so when the transcript ends on a tool result the payload's `last_assistant_message` is judged as that text — only then, since the transcript is the record of what the founder saw. It fires and blocks in a cloud session (measured 2026-09-21). Under `FS_HOST_NO_HANDOVER` the hook still never reads the ledger's flag: a closing call that is a shell call running the closer through python and printed the host line (`printed_from_result`, only with no hand-over opener in the result) makes that line the comparand, with its own `HOST_LINE_LEAD` block that never says "founder"; when the line also stands on its own line in a founder's own message of the prompt (`two_figures_check.no_handover_in`), nothing about the final message is judged (no containment, delivery or review-page ask), so a host's own memo passes, while the no-ask end check still runs (a refused closer is still named, without the word "founder"). With the host line printed but not in the request's own message, the delivery ask fires only when the model's own text links a file it did not attach.
- **PreToolUse** (`founder-skills/scripts/pretooluse-dispatch.sh` → `pretooluse_dispatch.py`), matcher `Agent|Task|AskUserQuestion|mcp__workspace__bash` (an exact list; `Bash` deliberately absent): ONE process runs every check in `CHECKS` order, first hold wins, each returning at its own tool-name and prefix tests. Seven checks: four on dispatches, which return at once on a question, two on the question tool, which return at once on a dispatch, and one on the shell, which a shell call runs alone (`SHELL_CHECKS`; no other call runs it). They run in the order `dispatch_type_check`, `asked_gate_check`, `two_figures_check`, `dispatch_prompt_check`, `no_ask_check`, `review_page_check`, `shared_tmp_check`; the numbers below are labels, not the order. (5) `no_ask_check.py`, on `AskUserQuestion`: denies every question in a prompt whose request carries `FS_HOST_NO_ASK` (or whose run's ledger records that the request carried the flag, read through this prompt's `start` result's ledger path, a regular file only), with no retry; the asked-gate and figures checks return at once on that line or on a ledger with the flag (theirs found through the dispatch's OUTPUT_PATH and `run_ref.json`, run id pinned in both), and the Stop hook, reading the ledger as this check does, then skips its delivery and review-page asks, still checks the printed hand-over, and otherwise asks once only when the run is left `running`. The ledger read is what covers a host that passes its request lines as the skill's arguments: they reach the transcript only in the skill's expanded text, which never counts. Per route: the dispatch checks read the ledger wherever the hook can open OUTPUT_PATH (at the Cowork host loop too, code-read from the same path; on a Cowork-local run the asked-gate check was observed reaching the run's hand-off folder, n=1); the `start` result's path is the session shell's, so at Cowork local the question tool and the end-of-turn check see no-ask only in the request's own message. The ledger records that the request carried a line, not that a person sent it; a shell can hand-edit it, and a held model can open the gate, resume the waiting run under the same id with an answer or no-ask line and open again (the host's own resume flow, so not refused; a test pins it as a residual): it is the first model-writable input that removes a hold rather than adding one, accepted because a forge buys one skipped hold, a forged no-ask makes the recorder refuse the model's own answers, and a forged pre-answer is disclosed (`two_figures_check.py`, THE ONE ARTIFACT READ). (0) `dispatch_type_check.py`, first: a dispatch whose first line (invisible characters removed) opens with one of the fleet's 25 context lines at a word boundary must name an agent its `CONTEXT_AGENTS` table lists — narrowed to the skills the transcript shows the session started (`Skill` calls, `<command-name>`), every one of them; with no `subagent_type`, `claude`, `general-purpose`, another skill's agent or another plugin's (`x:<name>`; only `founder-skills:<name>` or the bare name is ours) it is held naming the agent to send. A session that started no founder-skills skill and a prompt with no OUTPUT_PATH line is another plugin's and passes. `test_dispatch_type_check.py` derives the table from every fenced template line in SKILL.md and `references/` plus every context a SKILL.md asks a generator to print. No transcript: passes, with a stderr line only when the agent is wrong. (1) `dispatch_prompt_check.py`: a dispatch whose first line opens with a registered context at a word boundary (a suffix such as "(round 2)" is still that context) and whose agent is a `PAIRS` entry (market-sizing's RED_TEAM, CHECKLIST and its two sizing contexts, TOP_DOWN_METHODOLOGY / BOTTOM_UP_METHODOLOGY; competitive-positioning's four scoring/research contexts and its RED_TEAM; financial-model-review's CHECKLIST; deck-review's CHECKLIST) must equal, whitespace squashed, the latest printed prompt for its OWN `OUTPUT_PATH`. The comparand is a main-thread tool result paired by tool id with a shell block that runs a TRUSTED generator (from its own `skills/<skill>/scripts/` of an installed plugin — a Cowork, Desktop or CLI plugin mount or cache, the cloud skills mount, the folder the runtime loaded our skill from, or the hook's own — or as `$SCRIPTS/<generator>`; never while a plugin file differs from the hashes this version shipped with (`data/script-hashes.json`: every `.py` outside `tests/`, and agent files by the text after their front matter, which installers rewrite; an unlisted `.py` counts; no manifest, no check, one stderr line), nor after a file tool wrote over a generator, and a generator run from another plugin copy that exists on the hook's host is hashed where it ran; names read through the block's own assignments) and in which every other command is on an ALLOW-list of quiet commands (assignments, `cd`, `mkdir`, `ls`, `wc`, `test`, `true`, `set -e`, `cp`/`mv` with no `/dev` or `/proc` argument, the plugin's `resolve_artifacts_root.py` / `ocr_uploads.py` piped at most into `head`/`tail`/`wc`, and `echo` of literals and of `$?` or the block's own variables naming no context line); any other command, keyword, function or subshell and it is not a comparand. Or the generator is the block's last command (after `;`, a newline or `&&`) and what runs before it may print, provided each step is a plugin script or a known command that cannot leave anything running (no other interpreter, `exec`, `trap`, `awk`, `find`, or `sed` except `sed -n N,Mp FILE`) — the shape models use when they fold the generator into the previous step's block. A block setting `PATH`, `PYTHONPATH` and the like never counts, and `ls` is quiet only before the generator. Or a Read, or a quiet block's `cat`/`head`/`tail`, of the file a generator's stdout was redirected into or the runtime saved an oversized result to, dropped by any later write to it (a sub-agent's included), any later block that cannot be read or runs an interpreter other than the plugin's own scripts, or that writes or names a path it cannot resolve. A redo printed with `--correction producer-rejected --detail-file F` counts only when the transcript shows F written by a failed plugin producer run (`2> F`; the call exited non-zero, or the block's own `echo "EXIT=$?"` right after it printed a non-zero code) and not written since (reading it is fine); the SKILL.mds save it to `$HANDOFF_DIR/producer_rejected.txt`. The two blocks are matched on the file as written or its path through each block's own assignments; in a CLI `Bash` block that does not change folder, `$PWD` is the folder its transcript row records (never on the Cowork shell, whose row folder is the host's). Replayed over the kept run transcripts: 85 of 86 generator calls that printed a prompt are accepted (the other ran after an `if` block) and 7 of 7 redirects were paired (counted before the shared-folder rule below). A redirect into a file directly in `/tmp`, `/private/tmp` or `/var/tmp` never pairs, in its block or later: the folder is shared across sessions, so a failed redirect leaves another session's prompt under that name. `>&` to a file is a write. Else held with the printed prompt as the reason, or, when none exists, with a reason naming what to fix: the command that made the generator's block unvouchable, a redirect (run it again with no redirect), a generator that is not the plugin's own (or, when a plugin file differs from the shipped hashes, naming it, once per session under its own marker `[dispatch-check][plugin-files]`; after that hold every paired dispatch is still compared with its printed prompt and held when it differs, with a stderr line, but never rewritten to it, since a changed plugin's print is not sent into a dispatch; more than `max(5, 10%)` differing LISTED files means the manifest does not describe the install, and the check is off with one stderr line, while an unlisted `.py` is always named), or no printed prompt for this `OUTPUT_PATH` yet (run the generator in a call of its own or last in its block, nothing printing after it; every such hold names the generator and subcommand, `$SCRIPTS/<generator> <subcommand>`, says what `$SCRIPTS` is and lists the generator's identifier flags, never the hook's own folder; when this context's latest generator call refused -- an `is_error` result, or one opening with `[exit N]`, N not 0 (the Cowork host loop's shape), with no context line and a JSON line whose `status` is `rejected` or `refused` -- it echoes only the `code` (capitals and underscores) and says to do what the output says first, never on the stale head). With the generator last, its result is the comparand only for the context that generator printed, since what ran before it may print another context's line. Each check keeps its own marker (`[dispatch-type]`, `[dispatch-check]`) and its own budget. The type check: at most two holds per `OUTPUT_PATH`, then let through with a stderr line. The prompt check counts per `OUTPUT_PATH` and PHASE (`unprinted`, `printed:<sha>`, `stale:<sha>`, the sha the first 8 hex of the squashed print's sha256, carried in the hold as `[dispatch-check][<path>][p:<phase>]`): at most two per phase and four per path, the path's total checked first, then let through with a stderr line; a hold with no phase tag counts in every phase, and the `[plugin-files]` hold counts toward no path. Per phase because two "no printed prompt" holds on a CHECKLIST sent beside the step it reads used to spend the path's whole budget, so a later steered dispatch that needed a hold with the print inline went through unheld. Only the total bounds a path (the `stale:` sha is model-writable, the `printed:` sha changes on every differing reprint): a path that spent two `unprinted` and two `printed:` holds has none left for a `stale:` one, so an unvouchable redo then passes unheld, as it did after two holds before; the release gate's received-prompt check catches it. Sibling dispatches in one message can spend a phase twice in a turn, and a varied OUTPUT_PATH opens a fresh budget, both bounded by the total. Markers are found in the rows' decoded text, so any path counts. `OUTPUT_PATH` is the whole line, trimmed (local-lane paths contain a space); scoping by it separates skills and rounds, so a stale round's prompt sent verbatim to its own path passes and the newer round's missing hand-off fails `check_handoff.py`. A comparison redo printed by the generator (`--redo comparison`) is the comparand like any other: same OUTPUT_PATH, so a hand-written repair after it is rewritten to the redo, and the rewrite notice for a sizing context names it. An older print is never sent in a newer one's place: when the dispatch differs from the vouched print and the newest print for its context and `OUTPUT_PATH` in any main-thread shell or Read result (vouched or not, a failed shell result included; read from the text, never the command) differs too, the dispatch is held as if nothing were printed, asking for the same generator arguments in a shell call of its own, and after two holds in that phase (at most four on the path) it goes through as sent. The trade, accepted: a model-writable result (an `echo`, a `cat` of its own file) turns a rewrite into two holds and a pass, because a reverted redo is silent and falsifies the report while a pass after the holds reds the release gate's received-prompt check. No disclosure code is written from it -- compose reading a hook marker would make the report depend on the hook. **Rewrite:** where a printed prompt exists and the dispatch differs, the check instead allows it with `updatedInput` (the whole input, only `prompt` replaced) and an `additionalContext` notice ("do not send this dispatch again"; re-run the generator, and only a producer's rejection goes back through `--correction`), with no hold budget. It runs only at a transcript CLI `version` ≥ `REWRITE_FLOOR` (CLI 2.1.141), the lowest version observed to honour it (the sub-agent's result row records the replaced text; probed 2026-10-15 on CLI 2.1.141 with a minimal standalone hook, one sync `general-purpose` dispatch on a Haiku model, 2.1.286 as the control: the hook fired, the sub-agent answered the replaced prompt, the result row's `toolUseResult.prompt` was the replaced text and a `hook_additional_context` row carried the notice; the main thread's `tool_use` row keeps the prompt as sent, and at 2.1.286 the call ran async, its answer arriving in a `<task-notification>` row); below it the dispatch is held; only for an input carrying `subagent_type` and `description`; and never after a rewritten dispatch's result row showed a prompt other than the printed one. A hook `allow` does NOT skip a user or org rule: per the CLI's code (2.1.289) the rules are re-checked on the rewritten input, a `deny` rule still wins and an `ask` rule still prompts; a rewritten input missing a required key is denied by schema validation. Marker `[review-page-check]`, found in decoded text. An unattended host that asks no question never reaches it; the Stop hook's review-page ask covers a turn that ends at the gate. (6) `shared_tmp_check.py`, on the Cowork shell: denies a command that writes a fixed name directly in `/tmp`, `/private/tmp` or `/var/tmp` (every local Cowork session shares one `/tmp`, and another session's file there is not writable: the redirect fails, the command before it never runs, and reading the name back shows that session's output). Writes are read from the command's text: an output redirect, `tee`, `dd of=`, `truncate`, `sed -i`, a copy or move destination (a bare `/tmp` one writes the source's name there), any `-o`/`--output`/`--out` value except for the commands `_O_NOT_OUTPUT` lists, whose `-o` is a switch (`unzip`, `grep`, `ls`, `tar`, …) or a value that is not a file (`ps`, `ssh`, `set`, …); wget's document and log (`-O`, `-qO`, `--output-document`, `-o`, `-a` and their long forms; `-` is stdout); a script's own `-o`/`--output` after `bash X` / `sh X` (the shell's own `-o pipefail` before it is not a file); zip's archive and its `-O` (not under `-T`/`-sf`, which read it); tar's archive (`-f X`, `-czf X`, `--file=X`, the dashless `tar czf X`) under a create or append mode; the block's own literal assignments filled in, `${TMPDIR:-/tmp}` read as `/tmp` (bare `$TMPDIR` is not), a relative target after an in-block literal `cd /tmp` (a `cd` or assignment inside `( … )` ends with the subshell; a `case` pattern's `)` does not), heredoc bodies skipped. Never denied: anything left to expand, a folder below `/tmp`, reads, a copy out, a path a main-thread `mktemp` call printed, inline code (`bash -c`, `python3 -c`). Scope: the main thread started one of the six skills (`invocations`, so a skill name a tool returned does not count), or the command runs one of their scripts from an installed plugin (an unassigned variable or this checkout's own path does not count). A sub-agent's call (`agent_id` in the hook input, set only there) passes with a stderr line, since its holds land in the sub-agent's own transcript and could never be counted; no transcript passes. Marker `[shared-tmp][<path>]`, two holds per path on main-thread rows, then let through with a stderr line. Cost: nothing loads unless the command contains `/tmp`, and the transcript is parsed only on a hit. Residuals: a fixed folder below `/tmp`, a name set in an earlier shell call, a `cd` it cannot read, inline code (and the words after it, `bash -c "x" -o /tmp/y`), writes it does not model (a name the URL or server chooses: `curl -O`, `wget -P /tmp`; tar's archive named only by `TAPE`; `gtar` / `bsdtar`; a zip archive named after its `-x` / `-i` patterns; `touch /tmp/flag`, `python3 -m json.tool in /tmp/out`, `pushd /tmp && cmd > out`), false holds (a `case` inside `$( … )`, whose pattern `)` the shared substitution lifter reads as the end of the `$(`; a `case` with `in` on the next line or with no pattern; `zip -FF X --out Y`, which holds X too), the cloud remote-device shell (not in the matcher; a cloud container has its own `/tmp`).
- **Python floor for the plugin hooks: 3.9.** At the host loop the Stop and PreToolUse bodies run host-native on macOS under the system `python3` (3.9), where a 3.10 construct raises and the hook fails open; `test_hook_python_floor.py` checks every module a hook loads (and, where this machine has an older system python3, that each hook decides the same under it), and `pyproject.toml` lints those modules as py39.
- **pre-commit** (`scripts/hooks/pre-commit`): ruff format/lint on staged Python + the privacy-leak guard. Activate once per clone: `git config core.hooksPath scripts/hooks`. On a machine that has the private lists, also `git config --global founderskills.privacyLists required` and the same without `--global` in the main checkout (so a missing list fails a hook; `scripts/pre-tag.sh` checks it); a clone with hooks and no lists opts out with `git config founderskills.privacyLists optional`. All three privacy hooks run the guard beside the hook script (`scripts/hooks/../privacy_guard.py`; the work tree's own when none is there), so under this clone's absolute `core.hooksPath` every worktree runs the main checkout's guard. Bypass a confirmed false positive with `git commit --no-verify`.
- **commit-msg** (`scripts/hooks/commit-msg`): DCO gate — rejects a commit with no `Signed-off-by:` trailer matching the commit author. Validates only; it deliberately does not auto-append the trailer (a sign-off certifies that *you* have the right to submit, so a hook adding it silently would certify on your behalf). Then runs the privacy guard over the message (`--commit-msg`).
- **pre-push** (`scripts/hooks/pre-push`): the privacy guard over each pushed range's added lines and commit messages (`--range`), so a commit made with `--no-verify` is still checked before it leaves the machine.
