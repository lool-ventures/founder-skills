# IC Simulation Scripts

- **`fund_profile.py`** — Validates fund profile structure (archetypes, check size, thesis, portfolio). Partners are role names only: closed key sets (archetype `role` + `focus_areas`; portfolio `name` / `sector` / `status`; the top-level keys), and a source URL that is a person's page (LinkedIn `/in/` or `/pub/`, also behind `/mwlite/`; Crunchbase `/person/`; path percent-decoded, `https:/host` read as the host) is refused; codes `PARTNER_NAME_NOT_ROLE` (a `name` equal to the role label is tolerated and not written), `ARCHETYPE_FIELD_NOT_ALLOWED`, `FUND_FIELD_NOT_ALLOWED`, `PORTFOLIO_FIELD_NOT_ALLOWED`, `SOURCE_IS_A_PERSON`; a diagnostic names where, never the refused value, and on those codes withholds the archetypes, portfolio, sources and unknown keys from its stdout echo (any other refusal echoes the whole input, free text included: it reaches only the main thread that wrote it). `ROLE_LABELS` here is what compose renders the Fund Profile's partner labels from. With a run ledger, refuses (exit 10) until the mode and fund questions are recorded, refuses a profile whose `mode` is not the recorded fund choice (`GATE_RECORD_MISMATCH`), and refuses `RUN_FINISHED` on a delivered run. `--from-request` builds the profile from the run's recorded `ic_fund_mode=host_profile` value (a fund profile supplied with the request; the model never types it): the Step-1 caps again (`FUND_FIELD_TOO_LONG`, `FUND_FIELD_INVALID_CHARS`, via `_gates.fund_value_problem`), the request rules, the people rules, a closed `profile_source` stamp, written compactly and deterministically; `HOST_PROFILE_NEEDS_RUN` with no ledger, `HOST_PROFILE_REQUIRED` for a stdin profile on such a run. `founder_lines()` owns the fund's kind and provenance wording (compose renders it; the page must too)
- **`host_context.py`** — Steps 2-3: copies the kept items of the recorded `host_context` into `startup_profile.json` (it first applies a pending line Step 1 did not open, through `_ic_gates.require_or_exit`, and waits 10 / 12 on one that cannot be read; re-derived from the ledger; `GATE_RECORD_MISMATCH` on any disagreement; `HOST_CONTEXT_NOT_SUPPLIED` for a model-written block); no ledger is a no-op. `host_context_lines()` / `host_context_parts()` own the founder-facing wording. On an attended run a question only a request line can answer is never in `needs_input`: `open`, `host_context.py` and compose exit 10 with `request_waiting` (`open` then asks nothing else that turn), and the run stays `waiting` / `PRE_ANSWER_MALFORMED` for the corrected line's resume. Compose refuses a profile that disagrees with the run (`HOST_CONTEXT_MISSING`, also for a pending line no step applied; `HOST_CONTEXT_NOT_SUPPLIED`; and for the fund `FUND_PROFILE_SOURCE_MISMATCH`, also when a supplied fund has no profile), renders the kept items verbatim with a keep-set passed to both `substitute` and `scan`, and records `report.json.host_context`
- **`_ic_gates.py`** — ic-sim's gate checks for `fund_profile.py`, compose and the page: one run-id derivation (the id most of the run's files agree on), `RUN_ID_REQUIRED`, exit 10 naming the question, `RUN_FINISHED` on a `complete` run; `refuse_open_gates` / `coaching_pending` are `_ms_gates.py`'s, held equal by a test
- **`detect_conflicts.py`** — Validates agent-produced conflict assessments and computes summary stats
- **`persist_partner.py`** — Steps 6 and 6b's persisting step: pipes one partner's gated hand-off into `partner_{assessment,rebuttal}_<archetype>.json`, replacing any input `metadata` / `graded_against` with the run id and the fund-profile stamp. Refuses loudly (exit 1, `-o` untouched) a hand-off whose `partner` is another archetype (`PARTNER_MISMATCH`), an `-o` that is not that archetype's file (`OUTPUT_NAME_MISMATCH`), a dir with no readable fund profile (`FUND_PROFILE_MISSING`), a key outside the dispatch template's closed set for its kind, which also refuses a body of the other kind (`PARTNER_FIELD_NOT_ALLOWED`), and the same hand-off re-piped after the profile changed (`HANDOFF_NOT_REDISPATCHED`).
- **`score_dimensions.py`** — Scores 28 dimensions across 7 categories with conviction-based scoring; a missing or bad `--fund-mode` adds a `fix:` line with SKILL.md's line for it and the two choices
- **`compose_report.py`** — Assembles IC simulation artifacts into final report with cross-artifact validation; with a run ledger, refuses (exit 10) to write a Decline up until `ic_decline_confirmation` is recorded (owed only on a `pass`/`hard_pass` verdict). After the run gates it refuses (exit 1, nothing written, `FUND_PROFILE_NAMES_PEOPLE` in the `_ic_gates` rejection shape, so `compose_result.json` carries it) a `fund_profile.json` with a place for a person by the producer's own rules (`people_problems`: any key the producer would refuse, so a profile it wrote never trips it), which catches both a profile written before partners became role names and one written around the producer; the one exemption is an old generic profile's invented `background`. SKILL.md routes it to a rebuild from Step 4. Then, also before any write, it refuses `PARTNER_ARTIFACTS_STALE` (same shape, also in the host contract) when any of the six partner files, `conflict_check.json`, `discussion.json` or `score_dimensions.json` was not built from the current fund profile: `persist_partner.py` (Steps 6 and 6b), `detect_conflicts.py` (both paths), `compose_discussion.py` and `score_dimensions.py` stamp `graded_against.fund_profile` (the profile beside their `-o`, fingerprinted without `metadata` / `validation` / `accepted_warnings`, so accepting a warning stales nothing), and a missing stamp counts as stale in every mode (a pre-stamp run resumed under this version redoes Steps 5-8 once; a missing profile or artifact is left to `MISSING_ARTIFACT`). This is what makes the rebuild remedy real: rebuilding Step 4 alone no longer composes. `compose_discussion.py` refuses the same code (exit 1, `-o` untouched) when a partner file is unstamped or another profile's, so redoing Steps 7-8 alone after a rebuild does not re-stamp stale round-1/2 prose. What a stamp proves: the profile on disk when the script ran, which is the one the step's dispatch inlined only if the SKILL.md order was followed; a hand-written stamp still defeats it. `persist_partner.py` and `score_dimensions.py` also record `graded_against.source_sha256` (the hand-off bytes they consumed) and refuse `HANDOFF_NOT_REDISPATCHED` (exit 1, `-o` untouched, in the host contract) when the existing `-o` was built against an earlier profile from byte-for-byte the same hand-off: re-piping old hand-offs is not a redo. Never refused: a repeat under the same profile, or a missing / unreadable `-o`. Residuals: a one-byte edit of the old hand-off, or deleting `-o` first, passes; `detect_conflicts.py` is exempt (a clean `{"conflicts": []}` hand-off legitimately repeats byte for byte, and `--generic-stub` has no sub-agent at all). Posture shared with every ic-sim producer, not fixed here: `persist_partner.py` has no run gate (no `RUN_ID_REQUIRED` / `RUN_FINISHED`, `--run-id` not compared with the dir's ref), and its `-o` check is basename-only (another sim dir or a symlink is accepted) — the planned fleet-wide `OUTPUT_IS_INPUT` guard is the place for that. The page does not check staleness (it runs on finished runs, where no step can redo them).
- **`visualize.py`** — The report page on the shared `_ui.py` shell (verdict and conviction ring, key findings, the supplied context verbatim, the debate, all 28 dimensions as a filterable checklist with a `neutral` tone for a moderate result, the radar, the fund panel from `fund_profile.founder_lines()` / `illustrative_note()`, conflicts); outputs HTML (not JSON). Every page-built string goes through the founder-text policy with `host_context.keep_set` (the keep-set report.md uses, recorded as `report.json.host_context.keep_tokens`), then `_esc`. Refuses the same old profile with the same code (it has no run gate, so it also runs on a finished old folder).
- **`_ic_view.py`** — The one owner of the verdict sentence, thin-basis note, score text, partner verdict words (`VERDICT_WORD`: never a bare "pass"), ring tone and check-size text that report.md and the page share. Not a scoring file.
