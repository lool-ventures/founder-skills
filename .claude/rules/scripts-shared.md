# Shared Scripts

- **`founder_context.py`** — Per-company context management (init/read/merge/validate subcommands); protects 11 key metric fields. `read --run-id R --skill S` with a run ledger: each Step-1 field needs a record (exit 10 opens the missing ones and prints what to ask; exit 12 under `FS_HOST_NO_ASK`), a typed value must be the recorded one (exit 1 `GATE_RECORD_MISMATCH`), several contexts (or one, when the request answers `ctx_select_company` or its `ctx_basics.company_name` line names a different company, or `--expect-company` names one other than the single stored context's) make `ctx_select_company` owed (exit 10, was 2), and no context is `CONTEXT_NOT_FOUND` (exit 1). Without a ledger, byte-identical to before (goldens). Context supplied with the request is never founder context: `merge` refuses a payload carrying `host_context` (`HOST_CONTEXT_NOT_FOUNDER_CONTEXT`); every skill reads founder context at Step 1.
- **`find_artifact.py`** — Resolves artifact paths by skill name, artifact filename, and optional company slug
- **`insert_coaching.py`** — Deterministic Context B insertion: reads the sub-agent's commentary JSON, applies the 6-state idempotency matrix, replaces the per-run uuid `insertion_marker` with `## Coaching Commentary` + commentary in a single in-place write, and verifies `run_id` parity across `--verify-artifact` paths (exit 0 inserted/already_inserted; exit 1 blocked with JSON diagnostic). A usage error (exit 2) adds a `fix:` line with the insert command from the calling skill's own SKILL.md bash block, the skill read from `--report`'s `<skill>-<slug>` folder; with no known skill, both forms. Every skill's POST_COMPOSE_COACHING step calls it; sub-agents only compose commentary and never edit `report.md`. A report that declares `COACHING_REQUIRES_CHECK_RECORD` (cap-table's only) is inserted into only with a passing check record for that run (see `pool_claims_check.py`). With a run ledger, a successful insert marks the run `complete` (with `deliverables_status` `pending` where pages follow the coaching) and a block writes `running` / `COACHING_BLOCKED`; the status write never changes stdout or the exit code. A blocked diagnostic always goes to stdout and `-o` is left untouched; `-o` onto a file it reads, the report.json / report.md beside the report, or an existing file that is not its receipt is refused first (`OUTPUT_IS_INPUT`). In a dir carrying any run's `run_ref.json` it refuses an insert with no `--verify-artifact` (`RUN_ID_REQUIRED`) or whose artifacts' run is not bound there (`RUN_NOT_BOUND`); a `--report-json` whose top-level `run_id` is another run's is `RUN_ID_MISMATCH`, checked before anything is written (a missing id on either side is not compared). Each carries `code` and a model-facing `fix`. Unbound dirs: unchanged.
- **`check_handoff.py`** — Context A file hand-off gate: verifies a sub-agent's output file exists/parses as JSON and (optionally) that its receipt's `output_path` matches (`--agent-path` accepts the agent-namespace echo). Typed exit codes (0 ok / 3 missing-or-empty / 4 bad JSON / 5 path mismatch / 6 unparseable receipt / 7 content-shape invalid / **8 path-namespace mismatch**) for main-thread branching. Exit 8 fires when no file is at the expected path but one IS where a **doubled** agent-namespace prefix would have put it — reported ahead of exit 3 because the two are indistinguishable from the file check yet need opposite responses (3 = the receipt may be fabricated; 8 = the agent complied and the path was wrong). Its `found_at` is **diagnostic only**: never read the hand-off from it, or exit 0 stops meaning "the file is at the contracted path" for the ~50 downstream `$HANDOFF_DIR` references.
- **`merge_json.py`** — Shallow-merges multiple JSON object hand-off files (later files win; `--set key=value` overrides) into one stream for producer pipes — used when a step consumes the union of parallel sub-agent outputs (e.g. market-sizing "both").
- **`md_to_commentary.py`** — Transport envelope for Context B: the sub-agent writes coaching commentary as **plain markdown** (never JSON, never escaped), this wraps it into the payload `insert_coaching.py` reads. Quotes and line breaks in the commentary can't break the hand-off.
- **`_out_guard.py`** (plugin-root canonical, a byte-identical copy in each skill's `scripts/`, held by `test_out_guard_sync.py`) — refuses an output that names one of the call's own input files: the existing files on its command line (stdin never counts, so a stdin-fed in-place fix stays legal) plus the files it reads that argv does not name (`extra=`: a compose's or page's artifacts in `--dir`), by `realpath` and, when both exist, by inode. `in_place=` names a documented read-then-rewrite (market-sizing's `--replay sizing.json -o sizing.json`); `protect=` (the two receipt writers) also refuses an existing `-o` that is a canonical artifact or carries `metadata.run_id`, never an earlier receipt. Prints nothing on the pass path.
- **`resolve_artifacts_root.py`** — Resolves the canonical artifacts root AND the agent-namespace root (`--agent` / `--json`): in Cowork the sub-agents' file tools see the `outputs/` mount at a different prefix than the VM shell, so SKILL.mds derive `HANDOFF_AGENT` from `--agent` when building `OUTPUT_PATH` dispatch lines. Warns (never fails) when `--dir-name` names a directory with no mirror under the canonical root: a mistyped name still yields a well-formed path, and the symptom — every hand-off failing `check_handoff.py` exit 3 — reads as a fabricated receipt rather than a bad path, so the state machine spends its retry budget on redo-dispatches that cannot succeed. On a Cowork session tree the agent root is an ABSOLUTE host path: the main thread proves it once with `--set-host-outputs-dir` against a probe its Write tool wrote (exit 2 bad shape / 4 probe missing / 5 mismatch); until then, agent-namespace calls exit 6.
- **`_compose_result.py`** (one identical copy per skill's `scripts/`, held equal by a test) — every `compose_report.py` runs `main()` inside it. In a run dir carrying any `handoff/*/run_ref.json` it removes the earlier record on entry and writes `compose_result.json` on exit (exit code, codes, the gate waited on, the end of each stream; run id top level, never `metadata.run_id`, so it is never offered for reuse). Streams, argv handling and exit code are unchanged; a dir with no ref is untouched. Not a deliverable.
- **`_handoff_audit.py`** — Gate records: `check_handoff.py` writes `<file>.gate.json` (with its sha256 and `gated_at`, rewritten on every pass) on exit 0; each compose names every step with no record (`HANDOFF_BYPASSED`, medium, not acceptable where acceptance exists). The evidence is an ABSENT record, never something the fallback path writes. A missing `handoff/<run_id>/` is not silence: it means no records, so every step the artifacts show ran is named. Residual: a step required only because its hand-off file is in the dir (cap-table's per-document extractions, competitive-positioning's enrichment re-dispatch) stops being required when the dir is deleted, so deleting it can still remove that warning. A run that dispatched no sub-agent has none of those artifacts and is required to show nothing. Residual: hand-writing a gate record, or deleting a canonical artifact (which removes its step's requirement), still defeats it.
- **`_delivery_check.py`** — The Stop hook's delivery half (see `.claude/rules/hooks.md`): a successful report build whose files were linked but never attached, on a host that offered a delivery tool; and financial-model-review's review page left unsent by a turn that ended waiting at its values check. Loaded by path from `stop_handover_check.py`.
- **`pretooluse_dispatch.py`**, **`dispatch_type_check.py`**, **`asked_gate_check.py`**, **`dispatch_prompt_check.py`**, **`two_figures_check.py`**, **`no_ask_check.py`**, **`review_page_check.py`**, **`shared_tmp_check.py`** — the PreToolUse hook's body and its seven checks (see `.claude/rules/hooks.md`).
- **`script_hashes.py`** — The plugin's own files by hash, for the dispatch-prompt hook: `data/script-hashes.json` lists every `.py` outside the top-level `tests/` (folders starting `.` or `__` and files starting `.` skipped; `__init__.py` listed) and every `agents/*.md` by the text after its front matter (the synced and org installs rewrite front matter, not the body), CRLF folded to LF. A symlinked folder inside the plugin is not walked (its files read as missing). `--write` regenerates it, `--check` (optionally `--root DIR`) exits 1 naming what differs and how to regenerate, 0 when clean or when no usable manifest exists. `verify_detail` never raises: no usable manifest, or more than `max(5, entries // 10)` differing LISTED files, returns no list and a reason (fail-open); an unlisted script is always named and never counts toward that threshold. Python 3.9, loaded by the hook.
- **`_handover_check.py`** — The hand-over containment rule, in ONE place: the e2e lane and the Stop hook both ask whether the founder's message carries the printed message whole, and a rule with two copies drifts (the lane greens on one reading while the hook blocks on another). Link targets are dropped and whitespace squashed before comparing — the two runtimes render different links for the same file, and a re-typed indent is not a change. Containment, not digit-absence: a message is also wrong when it DELETES a printed line, which no digit check can see.
- **`_redteam_core.py`** — The adversarial review's skill-neutral half: which findings may reach a founder, and which review is shown (two reviews with no findings or rejected findings are compared by hand-off hash only, so a clean second round is a second review, not a copy). Both red-team skills load it by path; what differs per skill (the quote matcher, the review's wording, the parameter names a finding may name, what a review is taken against) is passed in.
- **`stop_handover_check.py`** — The Stop hook's body (see `.claude/rules/hooks.md`); loads `_handover_check.py` by path, since plugin-root `scripts/` is not a package.
- **`_gates.py`** — The gate registry and ledger. A `request_only` option (hidden; only a request line records it, `REQUEST_ONLY_OPTION` otherwise) carries a value checked at Step 1 by a filesystem-free predicate listed in `DRY_REQUIRES`; a value that cannot be read sets `pre_answer_malformed` beside `pre_answer_unlisted` and the run waits `PRE_ANSWER_MALFORMED`. `reads_in` names the skills that use a shared gate (`host_context`: ic-sim); the others list its line ignored as `not_used_by_skill`. Every `FS_HOST_VALUE` is capped at `VALUE_MAX` (32,768). `FS_HOST_REPLY_TOOL <tool_name> <input_key>` (no gate; two words, `REPLY_TOOL_NAME_RE` / `REPLY_TOOL_KEY_RE`, `REPLY_TOOL_REFUSED`) is recorded as `ledger.reply_tool` and shown as `run_status.json` `reply_tool` (a later line replaces it; `resume_prompt` never repeats it, because a pasted resume prompt is a founder row and the ledger's line is model-typed) for the record only (the Stop hook reads the line from the request's own message, never the ledger), and skills outside `REPLY_TOOL_SKILLS` list it `not_used_by_skill`. `FS_HOST_NO_HANDOVER` (no gate, nothing after it; refused beside a reply-tool line in one request, and on a resume that adds one to a run holding the other) is recorded as `ledger.no_handover`, sticky and never repeated by `resume_prompt`, read only by the three closers (`HANDOVER_SKILLS`, an alias of `REPLY_TOOL_SKILLS`); `run_status.json` shows `no_handover` and the closer's `handover: "host"`. One literal (`GATES`) names every question the six analysis skills ask, its options, who records it, its default reasons, when it is owed and whether a hook checks it was asked (`asked_check`). Ids are contract (change only by addition); labels are presentation, held to each skill's text by sync tests. The ledger is `<ARTIFACTS_ROOT>/runs/<RUN_ID>/gates.json`; every write takes the run lock, writes the ledger, settles which follow-ups are still owed (closing one no longer owed `not_applicable / script`, re-opening one owed again) and re-derives the status. Five gates are recorded by three scripts of their own (deck-review's `gate_state.py` for its three stage gates, market-sizing's `record_revision_answer.py`, cap-table's `extract_cap_table.py`), which keep their own files as mirrors; the recorder refuses those. A predicate that cannot decide for this run (an unreadable or other-run file) raises `GATE_UNDECIDABLE` (exit 2), never "not owed". What a record proves: a listed option was recorded for this run and, for a bound gate, what it confirmed has not changed — not that a person chose it. `--dump-contract` writes `data/host-contract.json`.
- **`_run_status.py`** / **`run_status.py`** — The status file a host reads (`runs/<RUN_ID>/run_status.json`, schema 1): `running` / `waiting` / `complete` / `refused` with a stable code, every gate of the skill and mode, `waiting_on`, `resume_prompt`, `disclosures`, `notices`, `deliverables` + `deliverables_status`, `handed_over_at`, and `invocations[]` (per invocation, which run-dir files it left untouched or rewrote, from a manifest taken at its start; null, never empty, when none could be taken). `start` takes `FS_HOST_RUN_ID=` or mints an id, validates every `FS_HOST_` line before the ledger exists (`PRE_ANSWER_INVALID` writes a `refused` status and exits 1; a later `start` under that id moves it to `run_status.json.replaced-<n>` and starts fresh) and resumes only a `waiting` run of the same skill; `RUN_ID_IN_USE` / `RUN_ID_FINISHED` are print-only (appended to `runs/<id>/start_refusals.jsonl`, never written to that id's status); `RUN_ID_MALFORMED` is printed and writes nothing. `bind` writes `<run dir>/handoff/<RUN_ID>/run_ref.json`, which is what tells a skill's own scripts the run has a ledger. Every bind (a re-bind included) stamps it with `bound_seq` (one more than the highest in the folder) and `bound_at`: the folder's current run is its newest bind (`folder_current_run`), read from the refs alone, and `superseded_by` stays the host-facing mirror. A compose-driven reopen from a folder other than the run's own (an archived copy) records that folder as the run's `run_dir_shell` and clears its own `superseded_by`, and marks no other run (`take_folder(from_dir=)`). `bind` and every reopen also take the run dir for that run (`_gates.take_folder_noted`): each other run whose listed files or unfinished work are in it is marked `superseded_by` it, one run lock at a time with a bounded wait; a marking that times out is a `SUPERSEDE_NOT_RECORDED` notice, retried by the run's later transactions at most once a minute, and a retry never takes the folder back. `finish --mode` ends a mode with no coaching; `fail --code` marks a run `refused` on a failure it cannot recover from (refused `RUN_WAITING` while a question is open); `deliverables --final` closes the page list. `check --skill S [--as-of]` is a dry run of `start` plus the request-only value checks (`_gates.dry_check`, only the predicates in `DRY_REQUIRES`; any other `requires` is `not_checked_here`): exit 0 accepted, 1 `start` would refuse, 4 a value would wait, 2 usage; writes nothing. `resumable` (`RESUMABLE_BY_SURFACE`) is `true` on `cli_artifacts_root` (a later, separate process over the same root resumed a waiting run) and `"same_session"` on every other surface until a new session there is shown to see an earlier one's files; moving an entry is a deliberate edit.
- **`record_gate_answer.py`** — The recorder. `open` writes `waiting` and prints `needs_input` (the question, the shown options, the exact `answer_command`) BEFORE the question is asked, or applies the request's pre-answer (`"applied": "pre_answer"`); `answer` validates every segment before writing any; `default --reason` takes only the registry's reasons (a refusal names the gate's); `not-applicable` takes several `--gate` (all or none). `derive` records an answer the request's `FS_HOST_DERIVE` line let the run take from the materials, with its source. A recorded answer stands (`ANSWER_STANDS`), except a default replaced by an answer, a bound answer whose binding changed, `--after-hold` once per run on a hook-checked gate, and a no-ask default replaced by a not-applicable record on the gates `NA_REPLACES_NO_ASK_DEFAULT` lists (`cp_product_availability`). Under `FS_HOST_NO_ASK` that replacement is the only `not-applicable` it takes (`NO_ASK_NOT_APPLICABLE` otherwise; not when the request named the gate in `FS_HOST_WAIT`), recorded with basis `model_no_ask` and disclosed `MATERIALS_STATED:<gate>` (keyed on that basis, so a record made before a resume added the flag is not listed); scripts' own not-applicable records are unaffected. `list` prints the host contract. Exit 0 / 1 rejected (ledger and status untouched) / 2 usage or unreachable / 10 waiting / 11 not owed / 12 waiting under `FS_HOST_NO_ASK` (nothing asked, nothing recorded by hand).
- **`_form_reply.py`** — Reads a Desktop question-form reply into gate answers, matched against the labels the form was built from, all or nothing. **Ships switched off** (`FORM_REPLY_ENABLED = False`): no live reply has been captured, so the recorder refuses `--form-reply` (`FORM_REPLY_DISABLED`) and the asked-gate hook ignores forms. Loaded by a hook, so Python 3.9-clean.
- **`_run_ref.py`** (one identical copy per skill's `scripts/`, held equal by `test_run_ref_sync.py`) — "does this run have a ledger?", answered from the run dir alone (`handoff/<RUN_ID>/run_ref.json`). With no ref a skill script takes its old path and loads nothing shared; with one it loads the shared modules by path (`load_shared`), which raises when they are unreachable. It also answers who owns a folder without loading anything: `folder_current_run` (the newest bind, by `bound_seq`; source-equal to `_run_status`'s), `refuse_not_this_runs` (in a folder that carries any ref: `RUN_ID_REQUIRED`, `RUN_NOT_BOUND`, `RUN_SUPERSEDED` for an id a later bind replaced, `ARTIFACT_OTHER_RUN` for a run file the step reads that carries another id, files under `handoff/` and outside the folder not compared), and `compose_run_or_exit` (compose's run is the folder's, never the artifacts'; required artifacts must carry it, another run's optional one is read as absent). Every producer that reads run files by path passes them (`test_folder_ownership.py`'s parity scan, exemptions by `(script, flag)` with a reason).
- **`data/host-contract.json`** — Generated by `_gates.py --dump-contract`, never hand-edited; a test holds it equal to the registry. What a host builds against: request-line grammar, gates and options (`pre_answerable`, `takes_value`), status fields, codes, exit codes, `resumable`, and the notes.
